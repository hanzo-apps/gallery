Approvals

Humans in the loop,
exactly where it counts. nowhere else.

Policies pause a run before a risky tool call: a large refund, an email to thousands, a SQL write. The right person approves, rejects or edits the arguments, and the agent carries on.

Refund Assistant

Policy: Refunds over $250

High risk

Issue refund $420 to customer #8812

issue_refund({"payment_id":"pi_8812x4010", "amount":420, "currency":"usd", "reason":"damaged_item", "customer":"#8812"})

“The order arrived damaged 6 days ago and the customer attached a photo. Policy §2.1 allows a full refund within 30 days, so I want to refund $420 to the original card.”

1h 40m left

What you get

Built for agents, not for API calls.

Policies, not code

If tool = issue_refund and amount > $250, require a Support Lead. Change thresholds without a deploy.

Edit & approve

Fix the arguments before approving: lower the amount, trim the recipient list, scope the SQL.

Context in one place

The agent's reasoning, the customer history and the trace, right next to the decision.

SLAs and escalation

Every request has a deadline. Unanswered requests escalate to a backup approver.

Approve from Slack

Approvers get a message with the context and buttons. No context switch needed.

Audit trail

Who approved what, when and why, exportable for your auditors.

How it works

Live in an afternoon.

policies.ts
fernline.policy({
  tool: "issue_refund",
  when: (args) => args.amount > 250,
  approver: "role:support-lead",
  sla: "2h",
});
